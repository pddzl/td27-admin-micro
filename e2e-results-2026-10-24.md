## Defects Found and Fixed This Run

1. **Dashboard bound camelCase against snake_case wire** (J5 root cause) —
   `web/src/api/sysMonitor/dashboard.ts`, `pages/dashboard/index.vue`,
   `components/SystemStatus.vue`, `components/RecentActivity.vue` rewritten to
   the actual wire (`user_count`, `uptime_seconds`, `{list:[...]}` envelope).
   Retested 15/15.
2. **Role create pushed junk row** — `roleCreateApi` returns `{success:true}`;
   page pushed it into the table. Now refreshes via `getTableData()`.
3. **Deactivated accounts could log in** (J10) — `rpc/basis` Login now returns
   `PermissionDenied "account is disabled"` when `user.Active` is false.
   Note: existing tokens persist until natural expiry (stateless JWT).
4. **File journey broken end-to-end** (J9 cluster):
   - Gateway `UploadFile` decoded a JSON body while the UI (el-upload) posts
     multipart → always "invalid request body". Handler now parses the
     `file` multipart part.
   - `allowed-ext` config lacked `.csv` while the UI only permits CSV — added.
   - Frontend download/delete called by-name routes that don't exist
     (`GET /file/download/:id`, `POST /file/delete {id}` are the real
     contracts) — `web/src/api/sysTool/file.ts` + page aligned.
   - Table bound camelCase fields; wire is `file_name`/`created_at` — aligned.
5. **RBAC policy/action mismatch for `/file/delete`** — permission row 235
   stored `action='read'` but the gateway maps the `/delete` suffix to action
   `delete`, so even root got 403. Fixed by
   `scripts/009_align_file_delete_action.sql` (idempotent) + policy reload;
   full audit of all api-domain rows found no other mismatch.

## Observations Logged (not fixed)

- **JWT signing secret is the static string `pddzl` committed in
  `api/gateway/etc/gateway.yaml`** — a token forged with it passed full auth +
  RBAC as admin during this run (used to recover access after logout).
  Move the secret to a per-environment secret store; rotate in k8s
  `gateway-config`.
- **Axios error handler reads `response.data.message` but the gateway sends
  `msg`** — users see generic 请求错误/拒绝访问 instead of server reasons.
- **User-create form defaults 状态 to 禁用** (backend default is active).
- **rpc error text leaks internals** (e.g. "file extension .exe is not
  allowed", "username doesn't exist") in gateway `msg`.
- **`POST /menu/user-menus` was a dead endpoint** (no consumer found) —
  removed since: route, HTTP handler, action-mapping suffix, and permission
  row retired via `scripts/010_drop_dead_user_menus_endpoint.sql`. The gRPC
  `GetUserMenus` method remains (live callers: sidebar `/menu/list` and the
  role-menu assignment handlers).
- **`/file/list` ignores `name`/`orderKey`/`desc`** — the page's search box
  and column sort are visual no-ops (backend `PageReq` has no such fields).
- **Upload response omits `file_id`** (`omitempty` + sqlx row not refetched);
  the frontend refreshes the list so it is unaffected.
- **Button-permission cache is a module singleton** — swapping tokens without
  a full page reload can show stale buttons (observed once mid-test;
  clean-room run is authoritative: hiding works).
