Compact guidance for AI agents working in this repository. Only includes repo-specific, non-obvious facts.

## Quick Overview
- Go 1.25 monorepo for gRPC admin microservices using go-zero v1.9.4
- Single service currently: `basis` (authority/access control service)
- Tech stack: gRPC, GORM, MySQL, go-zero framework
- No custom scripts, CI, or testing setup yet - all standard go-zero conventions apply

## Project Structure
```
/
├── rpc/                 # All gRPC service implementations
│   └── basis/           # Basis authority service
│       ├── proto/       # Protobuf definitions
│       ├── types/       # Generated gRPC/pb Go code
```

## Key Commands
All commands run from repository root:

### Build/Run
```bash
# Build basis service
go build rpc/basis/basis.go

# Run basis service (loads config from specified file)
go run rpc/basis/basis.go -f rpc/basis/etc/basis.yaml
```

### Protobuf Generation
Use goctl (go-zero CLI tool) for protobuf code generation:
```bash
# Generate from root service proto
goctl rpc protoc rpc/basis/basis.proto --go_out=./rpc/basis/types --go-grpc_out=./rpc/basis/types --zrpc_out=./rpc/basis -m

# Generate from subdirectory proto files (user/role/common)
goctl rpc protoc rpc/basis/proto/authority/user.proto --go_out=./rpc/basis/types --go-grpc_out=./rpc/basis/types
goctl rpc protoc rpc/basis/proto/authority/role.proto --go_out=./rpc/basis/types --go-grpc_out=./rpc/basis/types
goctl rpc protoc rpc/basis/proto/common/common.proto --go_out=./rpc/basis/types --go-grpc_out=./rpc/basis/types
```
**Required after modifying proto files**: Run the relevant generate command + `go mod tidy` + restart service.

## Configuration
- Service config: `rpc/basis/etc/basis.yaml` (YAML format)
- Loading mechanism: Entry point accepts `-f` flag pointing to config file (default: `etc/basis.yaml`), loaded via go-zero `conf.MustLoad()`
- gRPC reflection is automatically enabled in dev/test mode only

## go-zero Conventions & Gotchas
### Standard Patterns
- Business logic lives in `internal/logic/` - one file per RPC method
- Shared dependencies (DB pool, clients) are initialized once in `internal/svc/servicecontext.go`
- Generated code is stored in `types/` directory mirroring proto structure
- Use type-safe client wrappers generated by goctl for cross-service calls

### Important Gotchas
1. Never compare gRPC errors directly - always use `status.FromError(err)` and check gRPC status codes
2. Reuse gRPC client instances to avoid goroutine leaks (default generated clients create new instances on every call)
3. Proto files must set `option go_package = "./<output-path>";` for goctl generation to work correctly
4. Protoc plugins `protoc-gen-go` and `protoc-gen-go-grpc` must be in PATH for code generation
5. Service discovery keys (etcd) must match exactly between server and client configurations (convention: `<service-name>.rpc`)
